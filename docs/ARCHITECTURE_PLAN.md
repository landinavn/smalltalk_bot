# Small Talk — целевая архитектура

## 1. Главный принцип

Small Talk — единый продукт с двумя платформенными каналами: Telegram и MAX.

Нельзя создавать две независимые реализации обучения, профилей, подписок или AI-логики.

## 2. Целевая схема

Пользователь
    |
    +-- Telegram Mini App / Telegram Bot
    |
    +-- MAX Mini App / MAX Bot
              |
       Платформенные адаптеры
              |
       Общее backend API
              |
       Общее ядро Small Talk
              |
    +---------+-----------+
    |         |           |
  Users    Lessons     Subscriptions
    |         |           |
    +---------+-----------+
              |
       Общая база данных
              |
       AI / Speech services

Frontend React должен использовать общее backend API. Платформенные различия должны быть изолированы в адаптерах.

## 3. Backend-модули

Предлагаемые логические области ответственности:

- Identity: пользователи и привязка платформенных аккаунтов.
- Profiles: профиль, настройки и уровень пользователя.
- Assessment: тестирование и определение CEFR.
- Lessons: темы, сценарии и управление занятиями.
- Conversation: контекст и логика диалога.
- Speech: распознавание и синтез речи.
- Avatar: состояние преподавателя и данные для синхронизации анимации.
- Progress: история и аналитика обучения.
- Billing: тарифы, подписки и учёт лимитов.
- Platform adapters: Telegram и MAX.

Это целевая декомпозиция, а не утверждение, что такие модули уже существуют в коде.

## 4. Frontend

Основной frontend:
- React;
- TypeScript;
- Vite;
- Three.js для 3D-сцены.

Планируемые экраны:
1. Приветствие и регистрация.
2. Тест определения уровня.
3. Выбор преподавателя.
4. Главный экран и каталог тем.
5. Экран голосового урока с постоянно видимым аватаром.
6. Личный кабинет.
7. Прогресс и история занятий.
8. Словарь и ошибки.
9. Подписка и оплата.

Telegram и MAX могут иметь разные механизмы авторизации и системные ограничения Mini App, но бизнес-логика и данные должны оставаться общими.

## 5. Голосовой сценарий

Целевой поток:

1. Получение голосового сообщения пользователя.
2. Проверка формата и размера аудио.
3. Распознавание речи.
4. Передача текста в общий conversation engine.
5. Формирование ответа AI.
6. Синтез аудио.
7. Передача текста, аудио и данных синхронизации аватара во frontend/платформу.
8. Сохранение истории и прогресса.

Для lip sync желательно использовать временные метки фонем или visemes. Наличие только MP3/WAV не гарантирует точную синхронизацию губ.

## 6. 3D-аватар

Нужен фотореалистичный Digital Human в формате GLB.

При выборе модели проверять:
- качество лица и текстур;
- лицевой риг;
- blink и движения глаз;
- blendshapes;
- visemes;
- совместимость с Three.js;
- производительность на мобильных устройствах.

Не считать TalkingHead генератором 3D-модели. Это возможный компонент отображения и анимации.

## 7. Единый пользователь

Внутренняя сущность пользователя Small Talk должна иметь собственный идентификатор.

Telegram ID и MAX ID должны храниться как отдельные привязки к этому идентификатору.

Безопасное объединение:
- подтверждение владения аккаунтами;
- защита от повторной привязки;
- проверка конфликтов;
- журналирование важных операций.

Не использовать имя или username как доказательство личности.

## 8. Данные и платежи

Профили, уровень, история занятий, бесплатный урок, подписка и лимиты должны быть общими для платформ.

Первый бесплатный урок — 15 минут на человека, один раз между платформами.

Учёт времени:
- не списывать время ожидания ответа AI;
- учитывать фактическое время занятия;
- обеспечивать идемпотентность операций;
- не допускать двойного списания.

Платёжные интеграции MAX и Telegram изучить отдельно по официальной документации. Не предполагать одинаковые API или правила.

## 9. Принципы реализации

- Сначала аудит существующего кода.
- Не переписывать работающий backend без необходимости.
- Изменения вносить небольшими этапами.
- Сохранять обратную совместимость API.
- Изменения БД — только additive migrations, без потери данных.
- Секреты — только в защищённой конфигурации, не в Git.
- Любые production-изменения — только после согласования.
